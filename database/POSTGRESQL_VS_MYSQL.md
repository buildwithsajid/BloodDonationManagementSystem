# PostgreSQL vs MySQL — and why BDMS moved to PostgreSQL

## 1. Quick comparison

| Aspect | MySQL | PostgreSQL |
|---|---|---|
| Type | Relational database (RDBMS) | Object-relational database (ORDBMS) |
| Philosophy | Simple, fast, easy to set up | Standards-compliant, feature-rich, extensible |
| SQL standard compliance | Good, with some MySQL-specific syntax | Very high, closer to the SQL standard |
| Auto-increment keys | `AUTO_INCREMENT` | `GENERATED ... AS IDENTITY` (or `SERIAL`) |
| Date/time column | `DATETIME` | `TIMESTAMP` |
| Boolean type | Alias for `TINYINT(1)` | Real `BOOLEAN` type |
| Insert-if-missing | `INSERT IGNORE` | `INSERT ... ON CONFLICT DO NOTHING` |
| Index creation in table | `INDEX name (col)` inside `CREATE TABLE` | Separate `CREATE INDEX` statement |
| Storage engines | Several (InnoDB is the default) | One unified engine |
| Complex queries / JSON / arrays | Supported, more limited | Stronger (JSONB, arrays, window functions, CTEs) |
| Concurrency | Row locking in InnoDB | MVCC (readers do not block writers) |
| Cloud hosting | Widely available | Widely available (Neon, Supabase, Vercel Postgres) |
| License | GPL (owned by Oracle) | PostgreSQL License (permissive, community-owned) |

## 2. Main differences in one line each

- **MySQL** is known for speed and simplicity, which suits read-heavy web apps.
- **PostgreSQL** is known for correctness, strict standards and advanced features, which suits complex data and growing systems.

## 3. Why BDMS uses PostgreSQL (Neon)

1. **Free cloud hosting.** Neon provides serverless PostgreSQL and can be created from Vercel's Storage tab, so no database server needs to be installed or managed.
2. **Strong data integrity.** BDMS relies on foreign keys, `CHECK` constraints (blood group, role, status, urgency) and unique keys. PostgreSQL enforces all of these strictly.
3. **Standard SQL.** The schema is closer to standard SQL, so it is easier to move between providers later.
4. **Proper `BOOLEAN` type.** Donor availability (`availability`, `new_status`) maps to a real boolean.

## 4. What changed in the project

| Area | Before (MySQL) | After (PostgreSQL) |
|---|---|---|
| Driver (`pom.xml`) | `mysql-connector-j` | `postgresql` |
| JDBC URL | `jdbc:mysql://localhost:3306/...` | `jdbc:postgresql://HOST/DBNAME?sslmode=require` |
| Driver class | `com.mysql.cj.jdbc.Driver` | `org.postgresql.Driver` |
| Configuration | Hard-coded URL | `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `PORT` environment variables |
| Schema file | `database/schema.sql` | `database/schema-postgres.sql` |

Schema conversion details:

- `AUTO_INCREMENT` became `GENERATED BY DEFAULT AS IDENTITY`.
- `DATETIME` became `TIMESTAMP`.
- `INDEX` lines inside tables became separate `CREATE INDEX IF NOT EXISTS` statements.
- `INSERT IGNORE` became `ON CONFLICT DO NOTHING`.
- `ENGINE=InnoDB`, `CHARSET` and `COMMENT` clauses were removed because they are MySQL-only.
- `setval(...)` statements were added so that new rows get ids after the seeded ones.

## 5. What did NOT change

- All Java code (controllers, services, entities, repositories) is the same. Spring Data JPA and Hibernate hide most database differences.
- The JSP pages, CSS and JavaScript are the same.
- The six tables and their relationships are the same.

## 6. Short explanation for presentations

> "BDMS originally used MySQL. We migrated to PostgreSQL because it is hosted free on Neon through Vercel, enforces data integrity strictly, and follows the SQL standard more closely. Only the database driver, configuration and schema syntax changed, and the application logic stayed the same."
