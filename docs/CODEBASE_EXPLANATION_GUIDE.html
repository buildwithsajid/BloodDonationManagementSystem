CODEBASE EXPLANATION GUIDE

Exhaustive File-by-File Breakdown: Backend & Frontend Architecture
Blood Donation Management System (BDMS) • Advanced Java Programming • GNIMS Mumbai

PART 1: BACKEND ARCHITECTURE & ALL FILES

1. Configuration & Application Bootstrap

src/main/java/com/bdms/BloodDonationManagementSystemApplication.java
Role: Application Entry Point & Spring Boot Starter

The main class annotated with @SpringBootApplication. Initializes the Spring ApplicationContext, starts the embedded Tomcat server on port 8080, and triggers package scanning across com.bdms.

  • Concepts Used: Inversion of Control (IoC), Framework Bootstrapping, JVM entry point.
src/main/java/com/bdms/ServletInitializer.java
Role: WAR Deployment Initializer

Extends SpringBootServletInitializer and overrides configure(), allowing the application to be deployed as a standard WAR file on external enterprise servlet containers (Apache Tomcat, WildFly).

  • Concepts Used: Jakarta Servlet 6.0 Specification, WAR Packaging Lifecycle.
src/main/java/com/bdms/config/PasswordConfig.java
Role: Cryptographic Security Bean Definition

Defines a Spring @Bean returning a singleton instance of BCryptPasswordEncoder(). Injected into authentication and registration services to salt and hash passwords.

  • Concepts Used: Dependency Injection (DI), Cryptographic Key Derivation (BCrypt 10-round salt).
src/main/resources/application.properties
Role: Core Application Configuration

Configures database connection parameters (MySQL port 3306), Hibernate DDL validation mode (ddl-auto=validate), and sets Spring MVC JSP view resolution prefix (/WEB-INF/views/) and suffix (.jsp).

  • Concepts Used: Declarative Configuration, Environment Fallback Variables (${DB_PASSWORD:root}).

2. Domain Enums

src/main/java/com/bdms/enums/UserRole.java

Defines role-based access levels: ADMIN and DONOR. Used in session verification and route authorization.

src/main/java/com/bdms/enums/AccountStatus.java

Defines account standings: ACTIVE and INACTIVE. Governs account suspension workflows.

src/main/java/com/bdms/enums/RequestStatus.java

Represents blood request lifecycles: PENDING, IN_PROGRESS, FULFILLED, CANCELLED.

src/main/java/com/bdms/enums/UrgencyLevel.java

Clinical emergency classification: NORMAL, URGENT, CRITICAL.

3. Custom Domain Exceptions

src/main/java/com/bdms/exception/BusinessRuleException.java

Unchecked runtime exception thrown when domain rules fail (e.g., date in future, invalid status transition). Prevents invalid database transactions.

src/main/java/com/bdms/exception/ResourceNotFoundException.java

Unchecked runtime exception thrown when an entity is not found by ID or email.

4. JPA Persistence Entities

src/main/java/com/bdms/entity/User.java

Maps to the users table. Stores account credentials, email, hashed password, role, and account status.

  • Concepts Used: @Entity, @Table, @Id, @GeneratedValue, @Enumerated(EnumType.STRING).
src/main/java/com/bdms/entity/Donor.java

Maps to donors table. Contains medical donor attributes: DOB, phone, gender, city, area, last donation date, and live availability flag.

  • Concepts Used: @OneToOne with User, @ManyToOne with BloodGroup.
src/main/java/com/bdms/entity/BloodGroup.java

Lookup entity mapping to blood_groups table holding the 8 supported blood groups.

src/main/java/com/bdms/entity/BloodRequest.java

Maps to blood_requests table. Represents hospital requisitions with patient name, required units, hospital, city, urgency, and status.

src/main/java/com/bdms/entity/DonationHistory.java

Maps to donation_history. Captures completed clinical donations with donor reference, date, venue, and verifying administrator.

src/main/java/com/bdms/entity/DonorAvailabilityHistory.java

Maps to donor_availability_history. An immutable audit record capturing previous status, new status, and timestamp.

5. Data Transfer Objects (DTOs)

src/main/java/com/bdms/dto/ (11 DTO Files)

LoginRequest, RegisterDonorRequest, UserResponse, DonorResponse, AvailabilityUpdateRequest, AvailabilityHistoryResponse, BloodRequestCreateRequest, BloodRequestResponse, DonationCreateRequest, DonationResponse, BloodGroupResponse.

  • Concepts Used: Encapsulation, Mass-Assignment Protection, JSR-380 Bean Validation (@NotBlank, @Past, @Positive, @Pattern).

6. Repositories (Data Access Layer)

src/main/java/com/bdms/repository/ (6 Repository Interfaces)

UserRepository, DonorRepository, BloodGroupRepository, BloodRequestRepository, DonationHistoryRepository, DonorAvailabilityHistoryRepository.

  • Key Concept: DonorRepository employs @EntityGraph(attributePaths = {"user", "bloodGroup"}) to execute SQL joins in a single round-trip, eliminating Hibernate N+1 query overhead.

7. Service Layer (Interfaces & Implementations)

src/main/java/com/bdms/service/ & service/impl/ (12 Files)

Interfaces and their corresponding implementations: UserServiceImpl, DonorServiceImpl, BloodGroupServiceImpl, BloodRequestServiceImpl, DonationHistoryServiceImpl, DonorAvailabilityHistoryServiceImpl.

  • Concepts Used: Interface-based abstraction, @Transactional transaction boundaries, business validation, automatic date synchronization (updating donor.lastDonationDate during donation logging).

8. Controller Layer (Spring MVC)

src/main/java/com/bdms/controller/ (8 Controllers)
  • AuthController: Authentication, registration, session management, and root URL routing.
  • AdminController: Central administrative console with aggregate metric calculations.
  • DonorController: Donor dashboard, profile updates, and public donor search.
  • BloodRequestController: Hospital blood demand creation, search, and status updates.
  • DonationHistoryController: Verified blood donation logging and certificate views.
  • DonorAvailabilityHistoryController: Donor and administrative availability audit trails.
  • BloodGroupController: Visual blood group lookup.
  • UserController: Admin management of user account standing (Active/Inactive).

PART 2: FRONTEND ARCHITECTURE & ALL FILES

The presentation tier follows standard Jakarta Server Pages (JSP), JSTL 3.0, and a modular healthcare 5-color palette (Warm Alabaster #FFFDFB, Clinical Teal #0F766E, Vibrant Rose-Red #E11D48, Soft Mint #CCFBF1, Deep Charcoal #1E293B).

1. Modular Stylesheets & Scripts (`src/main/resources/static/`)

css/base.css

Declares CSS variables for the 5-color palette, global font settings, the 95% desktop layout container (max-width: 1280px), button components (.btn-primary, .btn-secondary, .btn-mint), and the 4-column clinical footer grid.

css/navbar.css

Implements the sticky top navigation bar (position: sticky; top: 0; z-index: 1000), Clinical Teal background (#0F766E), brand iconography, and role-based action buttons.

css/cards.css

Styles metric cards, clinical profile info grids, .blood-badge pills, the medical Hero Section banner, trust cards, and the FAQ accordion container.

css/forms.css

Formats medical input forms into clean 2-column grids with Clinical Teal focus highlights, validation error text, and filter bars.

css/tables.css

Provides healthcare tabular formatting with row hovers, urgency tags (.urgency-critical), and status pills (.status-available in Soft Mint).

js/main.js

Vanilla JavaScript controlling auto-dismissing flash alerts and the animated, smooth FAQ accordion expansion/collapse.

2. JSP Views (`src/main/webapp/WEB-INF/views/`)

common/header.jsp, navbar.jsp, footer.jsp

Modular layout templates. navbar.jsp renders dynamic links based on user role; footer.jsp displays the 4-column layout including GNIMS college details, department, tech stack, and team members.

donor/available-donors.jsp (Main Landing Page)

The core landing view featuring: (1) The Medical Hero Section with trust badges and CTA buttons; (2) The Donor Search Directory with telephone and email omitted to safeguard donor privacy; (3) The Smooth FAQ Accordion.

auth/login.jsp & register.jsp

Clean authentication forms featuring demo admin credential helpers and dynamic blood group dropdown selection.

donor/dashboard.jsp & profile.jsp

Donor portal displaying blood group badges, last donation records, and the interactive live availability switch.

requests/list.jsp, create.jsp, details.jsp, update-status.jsp

Hospital blood requisition screens for submitting emergencies, monitoring patient urgency, and updating fulfillment states.

donations/list.jsp, create.jsp, details.jsp, my-history.jsp, donor-history.jsp

Clinical donation screens allowing administrators to log verified donations and donors to review personal donation certificates.

admin/dashboard.jsp & user-details.jsp

Administrative management console displaying system KPI counters (Total Donors, Available Donors, Requests, Donations) and account standing toggles.

blood-groups/list.jsp & details.jsp

Visual directory of the 8 supported blood groups with direct search links.
