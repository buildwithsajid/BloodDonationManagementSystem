1. Executive Summary & Abstract

The Blood Donation Management System (BDMS) is a centralized web-based healthcare management platform designed to automate and accelerate the coordination between voluntary blood donors, patients, and hospital blood banks.

Traditional operations are challenged by outdated paper records, uncoordinated donor calls, and severe donor contact privacy breaches. BDMS introduces an architecturally robust solution that features:

  • Role-based access control for Donors and Administrators.
  • Instant multi-criteria search filtering by blood group (A+, A-, B+, B-, AB+, AB-, O+, O-) and city.
  • Strict Donor Contact Protection: Contact telephone numbers and email addresses are omitted from public directory tables to prevent spam and telemarketing harassment.
  • Clinical emergency requisition tracking with urgency ratings (NORMAL, URGENT, CRITICAL).
  • Immutable audit logging for donor availability state changes.

2. Objectives & Scope

Project Objectives

  • Digital Record Keeping: Replace manual logbooks with an ACID-compliant relational MySQL database.
  • Rapid Matching: Enable patients and hospital coordinators to locate nearby compatible donors in seconds.
  • Eligibility Governance: Track donors' last donation dates and enforce medical cooling intervals.
  • Administrative Accountability: Audit all availability updates and requisition status transitions.

Project Scope

  • In-Scope: Public donor directory, secure donor registration, session management with BCrypt password encryption, blood requisition lifecycles, clinical donation logging, and hospital requisition tracking.
  • Out-of-Scope: Real-time GPS coordinate mapping, SMS gateway dispatch (mocked via flash alerts), and online payment gateways.

4. System Architecture

The application adheres strictly to the Model-View-Controller (MVC) paradigm across a 3-Tier Layered Architecture:

  1. Presentation Layer (View): Server-rendered JSP templates styled with componentized CSS implementing a medical 5-color palette (Warm Alabaster, Clinical Teal, Vibrant Rose-Red, Soft Mint, Deep Charcoal).
  2. Controller & Business Layer (Controller & Service): Spring MVC controllers process incoming HTTP requests, validate input via Bean Validation (@Valid), enforce session security, and delegate to transactional service classes (@Transactional).
  3. Data Access & Persistence Layer (Model): Spring Data JPA repositories leverage Hibernate ORM to map persistent entities to MySQL tables, using @EntityGraph to eliminate N+1 query bottlenecks.

6. Syllabus Concepts Demonstrated (Advanced Java)

  • Java Collections Framework: Extensive use of List<T>, ArrayList<T>, and Optional<T>. Stream pipelines (.stream().map(...).filter(...).toList()) are implemented across all controllers and service layers.
  • Spring Boot & Dependency Injection: Constructor-based injection is utilized across all beans without @Autowired field injection to guarantee testability and immutability.
  • Database Connectivity & JPA: Complex derived queries, @EntityGraph eager-loading optimization, and declarative transaction management via @Transactional.
  • Bean Validation: Declarative validation annotations (@NotBlank, @Size, @Past, @Positive, @Pattern) coupled with Spring BindingResult.
  • Security: BCrypt salted hashing and session fixation defense via request.changeSessionId().
